# 产品需求文档（PRD）— ADS Plane v0.0.1 只读开发观察器

> 🌐 [English](../PRD-v0.0.1.md) | 中文（如与英文版冲突，以英文版为准）

状态：v0.0.1 已冻结

## 问题

使用多个 Web/本地 Agent、GitHub Issues/Dependencies、PR、精确 SHA 评审/验证与发布门禁的 AI 原生项目，会积累足以重建项目状态的持久证据，但 GitHub 的原生界面无法把这些状态呈现为一个连贯的运营视图。人们反复追问：哪些任务处于就绪/运行中/阻塞，哪些泳道可以并行推进，哪些证据已过期，哪个 Agent 负责当前工作，以及是什么阻碍了发布。

## 产品陈述

ADS Plane 读取 `ai-development-standard` 定义的 GitHub 与仓库持久事实，将它们确定性归约为项目/版本读模型，并把该读模型可视化为 `NON_AUTHORITATIVE_DERIVED_STATE`（非权威派生状态）。

GitHub/仓库事实始终是事实来源（Source of Truth）。ADS Plane v0.0.1 不具备任何 GitHub 写能力。

## 用户

- 协调多个 AI Agent 的项目所有者；
- 需要共享态势感知的构建/评审/验证操作者；
- 检查证据与收尾状态的发布负责人；
- 实际试用 `ai-development-standard` 的维护者。

## 主要用户旅程

1. 打开 ADS Plane，立即看到版本进度、候选/发布状态与活跃泳道。
2. 查看任务 DAG，理解真实依赖与可并行的工作机会。
3. 无需逐个检查 Issue，即可看到就绪/运行中/阻塞/可合并队列。
4. 识别哪个 Agent/调度正在处理某个任务。
5. 检查 CI/评审/验证证据，立即发现过期的精确 SHA PASS 证据。
6. 点击任务，查看依赖、PR 身份、调度、门禁与溯源。
7. 从 GitHub 重新同步，在没有任何聊天历史的情况下重建相同的派生状态。

## 功能范围

### 事实采集

读取仓库/默认分支身份、Issues、标签、评论、结构化 Agent 事件、原生 Issue `blocked_by` 依赖、拉取请求、工作流运行、`VERSION`、`.dev-standard/VERSION` 以及已知的任务 DAG 制品路径。

### 确定性归约

派生工作流状态、活跃阻塞、泳道进度、就绪集合、当前 PR 身份、CI/评审/验证门禁、过期证据、调度活动、候选状态与发布状态。归约器的决策必须是纯函数，且可由输入事实解释。

### 读模型/缓存

SQLite 存储仓库配置与最新 VersionSnapshot。删除数据库不得破坏项目权威；重新同步即可重建快照。

### UI

提供项目选择器、版本总览、指标、泳道进度、DAG、就绪队列、证据矩阵、调度活动与任务详情/溯源。

## 范围之外

- 不变更 Issue/PR/标签/依赖；
- 不做 Agent 调度或认领准入；
- 不执行评审/验证；
- 不做合并、候选冻结或发布资格动作；
- 不使用基于 LLM 的状态分类；
- 不做通用项目管理替代品；
- 不引入 Postgres 或分布式服务。

## 成功标准

- 配置好的 ADS 项目可以从 GitHub 事实归约为有效的 VersionSnapshot；
- 状态重建不依赖历史聊天；
- 原生依赖可用时优先使用；
- 过期的精确 SHA 评审/验证证据可见；
- 运行时适配器只暴露 GitHub GET 操作；
- 干净安装通过类型检查、测试与生产构建；
- 演示模式在无外部凭据的情况下展示所有主要状态。

## 发布阻塞项

- TypeScript 严格构建失败；
- 重放测试中出现归约器不确定性；
- 运行时出现 GitHub 写方法或写权限要求；
- 服务器无法以演示模式启动；
- Web 生产构建失败；
- 缺少安装/配置/架构文档。
